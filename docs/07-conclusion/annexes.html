Commandes Ollama

Commande Usage
ollama pull llama3.1:8b Télécharger un modèle
ollama run llama3.1:8b Charger + chat CLI (télécharge si absent)
ollama run llama3.1:8b "prompt" Exécution ponctuelle
ollama list Modèles sur le disque
ollama show llama3.1:8b Détails : contexte, paramètres, licence
ollama show modele --modelfile Retrouver la recette d'un modèle
ollama ps Modèles en mémoire, % GPU/CPU, échéance keep_alive
ollama stop llama3.1:8b Décharger de la mémoire
ollama rm llama3.1:8b Supprimer du disque
ollama cp llama3.1:8b dev Dupliquer sous un nouveau nom
ollama create revue-code -f Modelfile Créer un modèle personnalisé
ollama --version Vérifier l'installation

CLI conversationnel : /bye (quitter), /set verbose (latences, jetons/s), /show context (occupation de la fenêtre), """...""" (prompt multi-ligne), # (ajouter au prompt système).

Formules de dimensionnement (jour 1)

Poids (Go)          ≈ nb_paramètres(B) × octets/param
                      FP16 = 2 | Q8 ≈ 1 | Q5_K_M ≈ 0,69 | Q4_K_M ≈ 0,56
Raccourci Q4        : Go ≈ B ÷ 2          (7B → ~4 Go, 70B → ~40 Go)
Raccourci FP16      : Go ≈ B × 2          (7B → ~14 Go)
Cache KV / séquence ≈ 2 × couches × n_kv_heads × head_dim × num_ctx × batch × octets
                      (Llama 3 8B FP16 : 0,12–0,5 Go par 1000 jetons de contexte)
VRAM mono           ≈ poids + KV(1 séquence) + overhead(1–2 Go)
VRAM multi          ≈ poids + KV(1 séquence) × nb_utilisateurs + overhead
RÈGLE D'OR          : MÉMOIRE ≥ POIDS + CACHE KV + OVERHEAD
RAM/VRAM dispo Gamme Q4 réaliste
≤ 8 Go 3B–8B, contexte ≤ 8k
12–16 Go 8B–14B
24 Go 14B–32B
48 Go 32B–70B

Paramètres d'exécution essentiels

Paramètre Valeur « développement assisté »
temperature 0,2 (code/factuel) — 0,7–1,0 (conversation)
num_ctx 16384 (vérifier la mémoire du cache KV avec ollama ps)
num_predict 4096 (borner les réponses runaway)
seed fixe pour reproductibilité (démos, tests)
format "json" pour sortie parsable
keep_alive 5m défaut ; -1 serveur dédié ; 0 poste limité
num_gpu auto ; baisser si VRAM insuffisante
repeat_penalty 1,1 défaut ; 1,15–1,3 si boucles

Variables serveur : OLLAMA_HOST, OLLAMA_MODELS, OLLAMA_KEEP_ALIVE, OLLAMA_NUM_PARALLEL, OLLAMA_KV_CACHE_TYPE (q8_0/q4_0).

Installation express

# Linux
curl -fsSL https://ollama.com/install.sh | sh
# Docker Compose (extrait) : image ollama/ollama, port 127.0.0.1:11434,
# volume ollama:/root/.ollama, réservation GPU nvidia
docker compose up -d
# GPU dans Docker : pilote hôte + nvidia-container-toolkit, puis :
docker run --rm --gpus all ubuntu nvidia-smi

Windows 11 + WSL2 : pilote NVIDIA Windows uniquement (jamais dans Ubuntu) ; %UserProfile%\.wslconfig ([wsl2] memory/processors/swap) puis wsl --shutdown.

API HTTP

# Génération ponctuelle
curl http://localhost:11434/api/generate -d '{"model":"llama3.2","prompt":"...","stream":false}'
# Chat avec rôles + options
curl http://localhost:11434/api/chat -d '{"model":"llama3.2","stream":false,
  "options":{"temperature":0.2,"num_ctx":8192},
  "messages":[{"role":"system","content":"..."},{"role":"user","content":"..."}]}'
# Précharger un modèle (supprime la latence du 1er appel)
curl http://localhost:11434/api/chat -d '{"model":"llama3.2"}'

Endpoints : /api/chat, /api/generate, /api/tags, /api/show, /api/ps, /api/pull, /api/embed, /api/version — compatible OpenAI : http://localhost:11434/v1/chat/completions (clé requise mais ignorée).

OpenCode : configuration minimale (jour 2)

{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://localhost:11434/v1" },
      "models": { "llama3.1:8b": { "name": "Llama 3.1 8B (local)" } }
    }
  },
  "permission": {
    "edit": "ask",
    "bash": { "git push --force*": "deny", "git push *": "ask", "rm *": "deny", "*": "ask" }
  },
  "mcp": {
    "github": { "type": "remote", "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer {env:GITHUB_TOKEN}" } }
  }
}

Emplacements : commandes .opencode/commands/*.md — skills .opencode/skills/<nom>/SKILL.md — agents via opencode.json (mode: primary|subagent). Règle permissions : la dernière règle correspondante gagne (règles larges d'abord).

Fondamentaux des modèles

Terme Définition
IA Étiquette mouvante désignant ce que les ordinateurs parviennent nouvellement à faire de façon impressionnante — aujourd'hui les grands modèles de langage.
Machine learning (apprentissage automatique) Règles apprises à partir de données plutôt qu'écrites à la main.
Deep learning (apprentissage profond) Apprentissage par réseaux de neurones à plusieurs couches.
Transformer Architecture de réseau de neurones (2017, « Attention is all you need ») fondée sur l'attention ; base des LLM.
LLM (grand modèle de langage) Modèle Transformer entraîné sur un corpus massif pour générer du texte cohérent.
GPT (Generative Pre-trained Transformer) Famille de modèles fondée sur l'architecture Transformer.
Llama Famille de LLM open source de Meta AI.
Jeton (token) Unité atomique lue et écrite par le modèle ; ≈ ¾ de mot anglais ; le code inhabituel se divise en davantage de jetons.
Paramètre (poids) Nombre réel appris à l'entraînement ; figé après ; tout le « savoir » du modèle y réside.
Entraînement (training) Processus unique et coûteux qui règle les paramètres par prédiction du jeton suivant sur un corpus massif.
Inférence (inference) Exécution du modèle entraîné : paramètres en lecture seule, génération de jetons. C'est ce que fait Ollama.
Prédiction du jeton suivant Mécanisme unique du modèle : probabilités sur le vocabulaire, échantillonnage, ajout au contexte, recommencement.
Sans état (stateless) Le modèle ne conserve rien entre les requêtes ; la continuité vient du contexte renvoyé ou du harnais.
Date limite des connaissances (knowledge cutoff) Frontière temporelle de la connaissance paramétrique ; au-delà, inventions probables sans contexte fourni.
Connaissance paramétrique / contextuelle Savoir rappelé des paramètres (figé, flou sur le rare) / savoir lu dans la fenêtre (contrôlable, coûteux en jetons).
Quantization Réduction de la précision des poids : Q8 ≈ 1 octet/param, Q4_K_M ≈ 0,56 — divise la mémoire au prix d'une légère perte.
Fenêtre de contexte (context window, num_ctx) Nombre maximal de jetons vus à la fois : prompt système + historique + documents + réponse.
Cache KV Mémoire des vecteurs clé/valeur par jeton traité et par couche ; croît linéairement avec num_ctx et le batch.
Overhead Mémoire du moteur hors poids et cache KV (activations, buffers) : compter 1 à 2 Go.
Batching Traitement de plusieurs séquences dans le même passage GPU — clé du multi-utilisateur (vLLM, continuous batching).
Multimodal Modèle ingérant texte + image (voire audio) ; encodeur de vision et jetons d'image en plus.
Reasoning Modèle entraîné à produire une chaîne de raisonnement avant la réponse ; plus de jetons, plus de latence.
GGUF Format quantifié de llama.cpp/Ollama ; CPU et GPU, offload partiel.
Offload Répartition des couches du modèle entre GPU et CPU quand la VRAM manque (num_gpu).
RAM unifiée Pool mémoire partagé CPU/GPU (Apple Silicon) ; Ollama l'exploite via Metal.

Ollama

Terme Définition
Ollama Serveur local d'exécution de LLM : registre de modèles GGUF, API REST (port 11434), CLI, moteur llama.cpp.
Modelfile Recette déclarative d'un modèle personnalisé : FROM, PARAMETER, SYSTEM — ollama create.
keep_alive Durée de maintien du modèle en mémoire après la dernière requête (5m par défaut, -1 = toujours).
Endpoint compatible OpenAI /v1/chat/completions au format OpenAI — point de branchement des assistants IA.
stream Envoi de la réponse jeton par jeton (true, UI conversationnelle) ou JSON complet d'un bloc (false, scripts).
temperature / seed Aléa d'échantillonnage / graine de reproductibilité.
Function calling (tools) Sortie structurée (nom de fonction + arguments JSON) que l'application exécute ; nécessite un modèle entraîné pour les outils.

Harnais et agents

Terme Définition
Harnais (harness) Logiciel entourant le modèle : contexte, outils, autorisations, sessions — transforme le modèle en agent.
Agent Modèle + harnais + outils + fenêtre de contexte, échangeant des tours avec un utilisateur.
Session / tour / requête Hiérarchie : session (historique accumulé) > tour (un message utilisateur et tout ce qui s'ensuit) > requête (un aller-retour au modèle).
Outil (tool) Fonction exposée par le harnais au modèle : Read, Write, Bash, Search…
Appel d'outil / résultat d'outil Texte structuré émis par le modèle, exécuté par le harnais / ce que le harnais renvoie — unique vue de l'agent sur l'environnement.
MCP (Model Context Protocol) Protocole d'intégration d'outils externes : un serveur écrit une fois, utilisable par tout harnais compatible.
Commande Prompt pré-rédigé déclenché explicitement (/nom), avec template et $ARGUMENTS.
Skill (compétence) Savoir-faire chargé automatiquement selon la tâche ; SKILL.md avec description-déclencheur ; divulgation progressive.
Sous-agent (subagent) Agent délégué via un outil task : fenêtre de contexte propre, rapport unique au parent ; un seul niveau.
AGENTS.md Feuille de route permanente du projet, chargée en début de session ; conventions, commandes, interdits.
Système de mémoire Écriture de faits appris pendant la session + rechargement au démarrage — continuité entre sessions.
Divulgation progressive Ne charger que le contexte utile, le reste derrière des pointeurs de contexte.
Prompt système Instructions du fournisseur du harnais en tête de chaque requête ; prioritaire sur les messages utilisateur.
Permission / mode d'autorisation allow / ask / deny par outil ; modes : plan (lecture seule), défaut, modification automatique, YOLO.
Bac à sable (sandbox) Environnement isolé (conteneur, VM) bornant le rayon d'action des exécutions.
Environnement Le monde hors du harnais (système de fichiers…) ; seule couche qui persiste entre sessions.

Défaillances et pilotage

Terme Définition
Hallucination Sortie assurée mais erronée ; deux formes : exactitude factuelle (connaissance manquante → ajouter du contexte) et fidélité (dérive du contexte chargé → retirer du contexte).
Sycophantie Acquiescement complaisant produit pour plaire ; test : le modèle l'aurait-il dit sans votre influence ?
Budget d'attention / dégradation de l'attention Influence finie de chaque jeton, diluée quand le contexte grandit ; le signal se perd dans le bruit.
Zone intelligente / zone stupide Début de session vif / session saturée où la qualité chute — sans message d'erreur.
Non-déterminisme Même entrée, sorties possibles différentes ; réessayer est une stratégie légitime.
Réinitialisation / compactage / artefact de transfert Repartir vide / résumer en mémoire (avec perte) / écrire un fichier de relais dans l'environnement.
Source primaire / secondaire La chose elle-même (code, diff, transcription) / son récit (doc, résumé, description de PR) — la revue lit la source primaire.
Spécification / ticket Artefact décrivant un travail multi-sessions / unité délimitant une session ; taille cible : une session.
Questionnement approfondi (grilling) L'agent interroge l'utilisateur une décision à la fois avant de figer un artefact.
Vérification automatisée Contrôle déterministe (tests, types, lint) — alimente l'autocorrection de l'agent.
Revue automatisée / humaine Jugement d'un agent au contexte neuf / lecture du diff par le stagiaire — jamais la description.
Humain dans la boucle / AFK Travail supervisé en temps réel / agent lancé sans surveillance (bac à sable, PR finale).
Programmation au feeling (vibe coding) Accepter le code sans lire le diff ; posture de revue, acceptable sur prototype, pas sur code engageant.
DX / AX Expérience développeur (humains) / expérience agent : préparation de l'environnement pour un travailleur sans état.
